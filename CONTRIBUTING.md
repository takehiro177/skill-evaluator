# Contributing

Thanks for helping make skill evaluation honest and reproducible. This project
is deliberately small — a skill, two subagents, a handful of stdlib scripts,
and one static dashboard — so most contributions are docs, methodology
hardening, or small tool improvements.

## Project invariants (PRs must not break these)

1. **Every number is transcript-sourced.** Token figures come from the session
   transcript JSONL via `transcript_tokens.py`; quality verdicts come from the
   blind judge subagent. Nothing is estimated, reconstructed from memory, or
   computed by hand — an arm that can't be attributed is `unmeasured`.
2. **The judge stays structurally blind.** No arm identity, run markers, or
   token data may reach a judge prompt, and Response 1/2 positions stay
   randomized independently of arm A/B.
3. **Records are verbatim.** The `-records.md` companion carries the exact
   transcript text for each arm (HTML-escaped only). It must remain
   reproducible via `transcript_tokens.py --grep "<marker>" --full-text`.
4. **Agent tools stay dependency-free.** Everything in
   `skills/skill-evaluator/agent_tools/` except `deepeval_runner.py` runs on
   bare Python ≥ 3.9 standard library — no third-party imports, no network.
   CI smoke-tests this on 3.9 and 3.13; don't add a `pip install` to the
   workflow.
5. **deepeval is required and its outputs are kept.** The deepeval phase runs
   on every evaluation (or is explicitly marked `unavailable — <reason>`), and
   its `*.deepeval.{json,md,cases.json}` files stay in `reports/`.
6. **The dashboard is a projection.** A `*.summary.json` mirrors its report's
   transcript-sourced numbers exactly — never a second computation, never an
   estimate; unmeasured stays omitted or `"available": false`. The builder and
   template stay **stdlib-only, single-file, zero-dependency** (no CDNs, no
   build step, no third-party JS/CSS), so `reports/dashboard.html` keeps
   opening from `file://`. `reports/index.json` and `reports/dashboard.html`
   are generated by `build_dashboard.py` — regenerate them, never hand-edit.

## Dev setup & checks

```bash
git clone https://github.com/takehiro177/skill-evaluator
cd skill-evaluator
pre-commit install                      # ruff + ruff-format + hygiene hooks

# what CI runs:
pre-commit run --all-files
python -m py_compile skills/skill-evaluator/agent_tools/*.py
python skills/skill-evaluator/agent_tools/transcript_tokens.py --help
python skills/skill-evaluator/agent_tools/interaction_effects.py --help
python skills/skill-evaluator/agent_tools/combo_spec_builder.py --help
python skills/skill-evaluator/agent_tools/judge_planner.py --help
python skills/skill-evaluator/agent_tools/build_dashboard.py --help
python skills/skill-evaluator/agent_tools/build_dashboard.py --check --reports reports
claude plugin validate . --strict       # if you touched .claude-plugin/
```

To try the skill from the working tree without installing:
`claude --plugin-dir .` from the repo root.

## Repository layout (what lives where)

- `skills/skill-evaluator/SKILL.md` — the orchestrator procedure (Phases 0–7).
  Methodology changes go here **and** in `docs/`.
- `skills/skill-evaluator/agent_tools/` — the bundled scripts. Schemas live in
  each script's docstring; keep docstring and validator in sync.
- `skills/skill-evaluator/templates/` — report/records/combo templates and
  `dashboard.html` (the dashboard UI; data is injected at the
  `null /*__SKILL_EVAL_DATA__*/` token — keep that line exactly).
- `agents/` — the runner and blind-judge subagent definitions.
- `docs/` — architecture, methodology, token accuracy/measurement,
  combination-eval, dashboard.
- `reports/` — generated output; gitignored except the tracked worked examples
  (reports, records, deepeval/interaction/judge artifacts, `.summary.json`
  files) and the demo `dashboard.html` + `index.json`.

## PR notes

- Keep diffs focused; update the docs that describe what you changed.
- Schema changes to `*.summary.json`: additive optional fields are fine;
  anything breaking bumps `schema_version` in `build_dashboard.py` **and** its
  docstring, the validator, and `docs/dashboard.md`.
- Regenerating the dashboard updates the `generated_at` stamp inside
  `reports/index.json` and `reports/dashboard.html` — commit those two only
  when you intend to refresh the tracked demo.
- New example runs: track the full artifact set (report, records, deepeval,
  interaction/judge JSON where applicable, and the `.summary.json`) and add
  the matching `.gitignore` whitelist lines.
- Be honest in reports: negative and null results are first-class outcomes.
