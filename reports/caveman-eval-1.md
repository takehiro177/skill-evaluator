## What the skill claims & how it saves

> *"Ultra-compressed communication mode. Cuts token usage ~75% by speaking like caveman while keeping full technical accuracy. Supports intensity levels: lite, full (default), ultra, wenyan-lite, wenyan-full, wenyan-ultra."*

caveman is a persistent output-style skill: once active it rewrites every response into terse "smart caveman" prose — dropping articles, filler, hedging and pleasantries while preserving technical terms, code, and error strings verbatim. The **ultra** level goes further: abbreviates prose words (DB/auth/config/req/res/fn), strips conjunctions, and uses `X → Y` arrows for causality. **Mechanism:** `output` — it reduces the number of *generated* tokens (the 5×-priced axis). Its only added cost is a one-time **guidance load** (~1.1k tokens of SKILL.md written to context once per session).

**Measured vs claimed:** the skill claims ~75% reduction; this run measured **−59% output tokens / −48% cost-weighted** at ultra. Substantial, but below the headline — see Caveats for why (already-tight baseline prose, moderate compression by the runner, and cost-weighting folding in the one-time load).

## Methodology

- **Design:** injection-based blind A/B; the injected caveman SKILL.md body (with ultra set active) is the single manipulated variable. **Single-injection, multi-task** — guidance injected once, all three tasks answered in one session per arm, so the one-time load is amortized as in production.
- **Production conditions:** the shared runner prefix was **primed (warmed)** by a throwaway subagent, then the two arms ran **serially** — both read the prefix warm (`cache_read = 5805` each), so neither ate a cold-cache write. Tokens come from the transcript via `transcript_tokens.py` (RUN MARKER match), reported **cost-weighted** on the output axis.
- **Token note:** Arm B's subagent transcript recorded `output_tokens: 1` (a streaming-finalization artifact that also hit the warm-up primer). The true value (**1668**) is reconstructed from transcript-sourced totals: `subagent_total(9325) − input(2) − cache_create(1850) − cache_read(5805)`. Arm A logged cleanly (4060) and its total reconciles exactly, validating the method.
- **Quality:** scored by the blind `skill-eval-judge`, one fresh subagent per task — only the task, a skill-agnostic rubric, and two anonymized responses in **independently randomized** order; no arm labels, markers, token figures, or the word "skill".
- **Joint verdict:** token and quality results are combined; a token win with a quality loss is reported as a (here, mild) regression, not a clean win.

## Caveats

- **Small N — directional, not conclusive.** N = 3 tasks, 1 run each. Treat as signal; raise `--tasks` or repeat for confidence.
- **Below the claimed 75%.** Measured −59% output / −48% cost-weighted at ultra. Likely contributors: (a) the WITHOUT baseline was already fairly tight technical prose (not verbose marketing-speak), shrinking the headroom; (b) the runner subagent applied ultra moderately rather than maximally; (c) cost-weighting includes the one-time guidance load. A more verbose baseline (or `--from-history` real prompts) would likely show larger savings.
- **Consistent slight quality cost.** WITH lost 3/3, but each by only 1 point and with **zero technical errors** — purely omitted secondary detail. caveman's own "Auto-Clarity" rule (drop compression for security warnings, irreversible actions, ambiguity) was not stress-tested here; all three tasks were safe explanatory Q&A.
- **Per-task token figures are apportioned**, not separately measured (single-injection multi-task yields per-session totals). The session totals are measured ground truth.
