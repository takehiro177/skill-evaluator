## Methodology

- **Design:** injection-based blind A/B over **skill subsets**. Each arm injects a
  defined subset of the skills' bodies (baseline injects none, combo injects all);
  the injected subset is the single manipulated variable. Design =
  `<combined-vs-baseline | factorial-2 | leave-one-out | full-factorial>`,
  `<arms>` arms per task.
- **Interaction:** computed by `interaction_effects.py` as combined effect minus
  the sum of each skill's individual effect (excess-over-additive), per task and
  aggregated, cost-weighted on the billing axis. `<Marginal contributions for
  leave-one-out; pairwise terms for factorial.>`
- **Production conditions:** shared prefix **primed (warmed) + arms run
  serially**; per-skill one-time setup amortized (single-injection, multi-task)
  where the skills are persistent. Tokens from the transcript via RUN MARKER,
  **cost-weighted** (`--cost`), never the flat sum.
- **Quality:** blind `skill-eval-judge` per task makes the two decisive
  comparisons — **combo vs none** (does the stack help at all?) and **combo vs the
  best single skill** (does stacking beat just using the strongest one?) — each
  fed only the task, a skill-agnostic rubric, and two anonymized responses.
- **Joint verdict:** token and quality combined; a token win with a quality loss
  (or a combo that loses to a single skill) is reported as a regression.

See [`docs/combination-eval.md`](../docs/combination-eval.md) for the interaction
methodology and [`docs/token-accuracy.md`](../docs/token-accuracy.md) for the
cost-weighting rules, and
[`<combo-name>-combo-eval-<n>-records.md`](<combo-name>-combo-eval-<n>-records.md)
for the verbatim per-arm outputs.

## Caveats

- **Combination *when applied*, not co-triggering.** Like the single-skill eval,
  this injects the skills, so it measures what happens when both are *in effect
  together* — not whether they would both trigger on the same real prompt. Trigger
  overlap is a separate question.
- **Small N — directional, not conclusive.** N = `<N>` tasks, 1 run each. Interaction
  is a small difference of measured quantities, so it is the **noisiest** number
  here — raise `--tasks` or repeat before acting on a borderline call.
- **Cheaper default, less attribution.** `combined-vs-baseline` answers "does the
  bundle help?" but cannot attribute the effect to individual skills; use
  `--leave-one-out` / `--full-factorial` for that, at more arms/tokens.
