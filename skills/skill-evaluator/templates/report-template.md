## Methodology

- **Design:** injection-based blind A/B; the injected skill body is the single
  manipulated variable. `<For a persistent / output skill: single-injection,
  multi-task — the guidance is injected ONCE and several requests answered in one
  session, so the one-time load is amortized as it is in production.>`
- **Production conditions:** the shared prompt prefix was **primed (warmed) and
  arms run serially**, so no arm eats a cold cache write. Tokens come from the
  transcript via `transcript_tokens.py` (RUN MARKER match), reported
  **cost-weighted** (`--cost`) on the billing axis — never the flat sum.
  `<Note any normalization if priming was not possible.>`
- **Quality:** scored by the blind `skill-eval-judge` per task — only the task, a
  skill-agnostic rubric, and two anonymized responses in randomized order; no arm
  labels, markers, token figures, or the word "skill".
- **Joint verdict:** token and quality results are combined; a token win with a
  quality loss is reported as a regression.

See [`docs/token-accuracy.md`](../docs/token-accuracy.md) for the six rules behind
this report, and [`<skill-name>-eval-<n>-records.md`](<skill-name>-eval-<n>-records.md)
for the verbatim side-by-side arm outputs.
